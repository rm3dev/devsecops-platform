# Observability — metrics, logs, alerts, SLOs, notifications (Phase 10)

The monitoring stack was **installed** in Phase 2 (compose profile
`monitoring`: Prometheus, Alertmanager, Grafana, Loki, Alloy, node-exporter,
cAdvisor — all version-pinned, Traefik-routed, resource-limited). Phase 10
makes it **operational**: every scrape target reachable and authenticated, a
CI/CD + SLO + log-derived alert set, five provisioned Grafana dashboards, and
both notification paths (infrastructure → Alertmanager, pipeline → Jenkins
`notifyResult`) fed by one configuration script.

```
                       ┌────────────────────── scrape ─────────────────────┐
 traefik:8082  jenkins:8080/prometheus/  gitlab:9168  nexus:8081  vault:8200
 node-exporter:9100  cadvisor:8080  loki:3100  alloy:12345  alertmanager:9093
                       └──────────────► PROMETHEUS (rules: platform/cicd/slo)
                                              │ alerts                 ▲
                                              ▼                        │ log-alerts
                                        ALERTMANAGER ◄────────── LOKI ruler (embedded)
                                     slack│teams│email                   ▲
                                              │                          │ logs (healthcheck noise dropped)
                                              ▼                        ALLOY ◄─ docker-socket-proxy
                                     on-call humans            (all compose containers)

 GRAFANA: 5 provisioned dashboards (Prometheus + Loki + Alertmanager datasources)
 JENKINS: notifyResult → Slack/Teams/SMTP (pipeline events, master spec §16)
```

## 1. Scrape targets (monitoring/prometheus/prometheus.yml)

| Job | Endpoint | Auth | Enabled by |
|---|---|---|---|
| prometheus / alertmanager / loki / alloy / node-exporter / cadvisor / traefik | native | none (internal net) | P2 |
| vault | `vault:8200/v1/sys/metrics?prometheus-format=true` | none — `telemetry.unauthenticated_metrics_access` in vault.hcl (internal network only, deliberate) | P2 |
| jenkins | `jenkins:8080/prometheus/` | none (unauthenticated endpoint per JCasC `prometheusConfiguration`) | P3 plugin; **P10 added jenkins to monitoring-network** — before that the job was DNS-unreachable |
| gitlab-exporter | `gitlab:9168` | none | P10: omnibus exporters-only mode (`prometheus_monitoring=true` + bundled prometheus/grafana/alertmanager/node_exporter **off**; `gitlab_exporter` on 0.0.0.0:9168) |
| nexus | `nexus:8081/service/metrics/prometheus` | basic — zero-privilege `metrics` user, `password_file: /etc/prometheus/secrets/nexus_metrics_password` | P10: `monitoring/scripts/10-enable-nexus-metrics.sh` (capability + role + user; password generated by bootstrap so the Prometheus config ALWAYS loads) |
| sonarqube | — | — | Community Build exposes no metrics API (D-07); job template documented in prometheus.yml |

**Reload without restart** (config or secret changes):
`docker compose exec prometheus kill -HUP 1` (`--web.enable-lifecycle` is on:
`docker compose exec prometheus wget -qO- --method=POST http://localhost:9090/-/reload`
also works). Alertmanager reloads the same way (`kill -HUP 1`).

## 3. SLOs (D-33, rules/slo.yml)

| SLO | SLI | Objective | Budget |
|---|---|---|---|
| platform-availability | `avg(up{job=~"jenkins\|gitlab-exporter\|nexus\|vault\|traefik"})` — probe-style, recorded as `slo:platform_up:ratio` | 99.5% / 30d | 0.5% |
| service-availability | 1 − (Traefik 5xx rate / total rate) per `service`, recorded as `slo:traefik_service_success:ratio_rate{5m,30m,1h,6h}` | 99.9% / 30d | 0.1% |

Burn-rate alerting (Google SRE workbook, multi-window multi-burn-rate):

* **Fast burn 14.4×** (windows 5m AND 30m, `for: 2m`) → critical/page —
  budget gone in ~2 days.
* **Slow burn 6×** (windows 1h AND 6h, `for: 15m`) → warning/ticket —
  budget gone in ~5 days.

30-day availability and current burn are gauged on the **Platform Overview**
dashboard (`devsecops-overview`).

## 4. Dashboards (monitoring/grafana/dashboards/, provider folder `DevSecOps`)

| File | UID | Contents |
|---|---|---|
| `platform-overview.json` | devsecops-overview | targets up/down, 30d SLO gauge, burn-rate stat + windows, per-service 5xx ratio, scrape-target table, firing-alerts table (incl. Loki log-alerts) |
| `cicd-pipeline.json` | devsecops-cicd | Jenkins queue/executors/nodes/throughput/duration quantiles, GitLab Sidekiq top-10 + ruby memory, Nexus liveness, scrape durations |
| `infrastructure.json` | devsecops-infra | host CPU/memory/disk/network, container CPU/memory top-10, restarts/h, Prometheus TSDB head series (cardinality creep) |
| `security-vault.json` | devsecops-security | Vault seal state + leases + runtime memory, Traefik 4xx/5xx anomaly surface, auth-failure log-rate (Loki), Vault log tail, pointer to pipeline gate artifacts |
| `logs-platform.json` | devsecops-logs | ingestion rate/lines, Alloy+Loki liveness, volume by service, error-line rate by service (same expression family as the ruler alert), live platform-wide error stream |

Dashboards are **provisioned, not imported** — edit the JSON in git; Grafana
picks changes up within 60s (`updateIntervalSeconds`). Datasource UIDs
(`prometheus`, `loki`, `alertmanager`) are fixed by
`provisioning/datasources/datasources.yaml`.

## 5. Log pipeline (Alloy → Loki)

* Alloy discovers ALL compose containers through the **socket proxy**
  (D-04 — no raw Docker socket), labels streams `container`/`service`/`project`.
* Phase 10 inserts a `loki.process` stage that **drops healthcheck noise**
  (`/-/healthy`, `/api/health`, `wget -qO-` …) before ingestion — compose
  healthchecks fire every 30s per container and would dominate volume and
  poison error-rate log alerts (D-35).
* Loki monolithic mode runs the **embedded ruler**: file-based rules from
  `monitoring/loki/rules/fake/` (tenant `fake` because `auth_enabled: false`),
  alerting to the same Alertmanager routes. Retention 14d (compactor-enforced).

## 6. Notification paths (D-34)

**Two independent paths, one configuration script**
(`monitoring/scripts/20-configure-notifications.sh`):

1. **Infrastructure → Alertmanager** (alerts above): Slack incoming webhook
   (`api_url_file`), MS Teams Workflows webhook (`msteams_configs`,
   `webhook_url_file`), SMTP email (`auth_password_file` secret;
   smarthost/from/to/`auth_username` set inline by the script via yq). Routes: `severity=none` →
   watchdog sink · `critical` → oncall-critical (Slack+Teams+email, 1h repeat)
   · rest → platform-default (Slack+email, 12h repeat). Inhibitions: critical
   silences same-alert warnings; platform fast-burn silences TargetDown noise.
2. **Pipeline → Jenkins `notifyResult`** (master spec §16 events): same Slack
   Teams/SMTP endpoints, delivered from builds via JCasC credentials
   (`slack-webhook-url`, `teams-webhook-url`) + mailer. Events:
   `build_started/build_completed/build_failed`, `deployment_started/
   deployment_completed`, **`deployment_failed`** (Phase 10: fired by
   verifyDeployment/runPostDeploy the moment the verdict is in),
   **`rollback_executed`** (Phase 10: fired by rollbackDeployment for BOTH
   automatic and manual rollbacks, digest attached), `quality_gate_failed`,
   `critical_vulnerability`, `container_published`, `release_approved`.
   Dispatch is ALWAYS fail-safe — a notification problem never fails a build;
   unprovisioned channels skip with a warn.

**Fail-safe placeholders:** bootstrap.sh writes every `*_file` secret from day
one with parse-safe placeholder values (URL-shaped, host-shaped) because
Prometheus/Alertmanager validate file contents at config load — a missing file
would stop the container. Placeholders load cleanly; delivery fails per-alert
until the configure script runs.

**Watchdog as external uptime input:** an outside monitor can assert
`GET https://alertmanager.<domain>/api/v2/alerts?filter=alertname="Watchdog"`
(basic-auth via the `monitoring-auth` middleware) returns a firing alert;
absence = the whole alerting path is down.

## 7. Runbooks

```bash
# configure everything (from .env; prompts for SMTP password if unset)
./monitoring/scripts/20-configure-notifications.sh
docker compose up -d jenkins            # picks up new JCasC credential env

# enable the Nexus scrape target (after nexus/scripts/10-admin-bootstrap.sh)
./monitoring/scripts/10-enable-nexus-metrics.sh
docker compose exec prometheus kill -HUP 1

# verify end-to-end (Prometheus/Alertmanager are internal or behind the
# monitoring-auth middleware — query from inside the stack)
docker compose exec prometheus wget -qO- http://localhost:9090/api/v1/targets | \
  jq '.data.activeTargets[] | {job:.labels.job, health}'
docker compose exec prometheus wget -qO- http://localhost:9090/api/v1/rules | jq '.data.groups[].name'
docker compose exec alertmanager wget -qO- http://localhost:9093/api/v2/alerts | \
  jq 'map(.labels.alertname) | unique'                          # Watchdog present
docker compose exec loki wget -qO- http://localhost:3100/prometheus/api/v1/rules | \
  jq '.data.groups[].name'                                      # loki ruler loaded
# Grafana → Dashboards → DevSecOps folder: 5 dashboards, no "datasource … not found"

# fire a test alert through the whole path (Slack/Teams/SMTP if configured)
docker compose exec alertmanager wget -qO- --header='Content-Type: application/json' \
  --post-data='[{"labels":{"alertname":"NotificationTest","severity":"warning"},"annotations":{"summary":"Alertmanager path test"}}]' \
  http://localhost:9093/api/v2/alerts
```

## 8. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| target DOWN `jenkins` | jenkins lacks monitoring-network (pre-P10 compose) or plugin missing | `docker compose up -d jenkins` with current compose; plugin `prometheus` in plugins.txt |
| nexus scrape 401 | metrics user password ≠ password_file | rerun `10-enable-nexus-metrics.sh` (refreshes both sides) |
| Alertmanager crash-loops after edit | `*_file` missing or unparseable, or YAML/Go-template error | `docker compose exec alertmanager amtool check-config /etc/alertmanager/alertmanager.yml`; ensure bootstrap placeholders exist |
| Slack/Teams configured but silent | placeholder still in secrets file; or webhook bound to another channel | rerun configure script; incoming webhooks are channel-bound — `channel:` field is intentionally omitted |
| emails not sent | `SMTP_HOST` empty → global smarthost `smtp.invalid` | set SMTP_* in .env + rerun script; check `docker compose logs alertmanager` for per-send errors |
| Loki ruler alerts absent | rules dir not mounted / tenant dir name | must be `rules/fake/…` (auth_enabled=false); `curl localhost:3100/prometheus/api/v1/rules` |
| log volume suspiciously low | Alloy drop stage too aggressive | tune `stage.drop` expressions in config.alloy (healthcheck patterns only) |
| SLO gauges empty | recording rules need ≥ window length of data | wait 6h for 6h-window series; 30d gauge fills progressively |
| Jenkins metrics missing | `prometheusConfiguration.useAuthenticatedEndpoint=false` reverted, or endpoint path | `curl localhost:8080/prometheus/` on the controller |
