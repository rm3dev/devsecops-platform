(`SET_IN_PHASE_N`) until its provisioning phase replaces the environment value
and the controller container is recreated — a stage using an unprovisioned
credential fails loudly instead of silently skipping.

## 2. Role → access matrix (master spec §17)

### 2.1 Jenkins (implemented Phase 3 — `jenkins/casc/10-security.yaml`)

| Role (principal) | Key permissions | Explicitly denied |
|------------------|-----------------|-------------------|
| `admin`, `platform-admin` | Overall/Administer | — |
| `devops-admin` | Overall/Manage+SystemRead, Job/* configure/create/delete, Computer/*, View/*, Run/Update+Delete+Replay, Credentials/View | Overall/Administer (no plugin management, no global security edits) |
| `developer` | Job/Read+Build+Cancel+Workspace, Run/Update+Replay, View/Read | any Configure/Create/Delete; Credentials; Computer |
| `security-engineer` | Overall/SystemRead, Job/Read+Cancel, View/Read+Create, Run/Update | Job/Configure, Credentials |
| `release-manager` | Job/Read+Build+Cancel, Run/Update+Delete, View/Read | Job/Configure, Credentials, Computer |
| `app-owner` | Job/Read+Build+Cancel, Run/Update, View/Read | everything else |

Production sites swap the local realm for LDAP/OIDC; the matrix maps
principals, so only entry types change (`user:` → `group:`).

### 2.2 GitLab (implemented Phase 4)

| Principal | platform group | teams group | gitops-repository | shared-library |
|-----------|----------------|-------------|-------------------|----------------|
| `root` (break-glass) | Owner | Owner | Owner | Owner |
| `jenkins-ci` | — | Developer (clone app repos, commit statuses) | **Maintainer** (bot pushes digests to protected main) | Reporter (clone only — cannot push) |
| `argocd` | — | — | Reporter (read-only pulls) | — |
| Human developers | per team subgroup (Phase 6 seed) | Developer | — | — |
| Release managers | — | Maintainer of team subgroups | Maintainer (prod overlay reviews) | — |

Enforcement on CE: protected branches (`main` push=No-one on library,
Maintainer on gitops; force-push denied), protected tags (`v*`, `rel-*`),
"pipelines must succeed" (active once Phase 6 publishes commit statuses),
MR-only flow. Premium-gated additions (approval rules, CODEOWNERS enforcement,
push rules, group webhooks) are attempted by the scripts and activate
automatically under license (D-19).

## 3. Platform boundaries (summary — details in architecture.md §8)

- Single TLS ingress (Traefik); only 443/80/2222 published on the host.
- No Docker socket on the Jenkins controller; dynamic agents via allow-listed
  socket-proxy with **EXEC denied** (JNLP connector, D-17).
- Agents plane (`devsecops-agents`) is internal: no direct internet —
  dependencies exclusively via Nexus (D-16).
- Rootless BuildKit for image builds; `no-new-privileges` platform-wide;
  non-root uids per architecture §6.3; read-only rootfs in the prod overlay
  where images allow.
- GitLab→Jenkins webhooks travel the internal scm-network only (D-18).
- Images deploy by immutable digest, signed (cosign) and admission-verified
  (Kyverno) — Phases 7/8.

## 4. Security pipeline contract (from Phase 3 library, enforced Phase 7)

- Organization policy floor: `resources/security-policy-default.yaml`
  (critical/high block by default; secrets always block; SBOM + signing
  mandatory).
- Project overrides validated **tighten-only** — weakening a `block_on_*`
  flag or disabling `secrets`/`sbom`/`signing` fails the build.
- Exceptions register (`security-exceptions.yaml` per service): id, tool,
  owner, justification, approvedBy, expires — validated every run; expired
  exceptions are ignored and logged (findings gate again). Nothing is ever
  silently suppressed.

## 5. Security scanning platform (Phase 7 ✅)

| Tool | Runs on | Data source (offline boundary, D-24) | Gate |
|------|---------|--------------------------------------|------|
| gitleaks 8.30.1 | agent-security | local workspace (`--no-git`, stash has no .git) | `secrets.block_on_detection`; exceptions by RuleID/Fingerprint |
| semgrep 1.183.0 | agent-security | baked rulesets `/opt/semgrep-rules` (default, owasp-top-ten, security-audit) | `sast.block_on_critical/high`; ERROR→high mapping |
| trivy 0.76.1 (fs + image) | agent-security | vuln/java DBs via Nexus `ghcr-proxy` (docker-group) | `dependencies.*` (fs) and `container.*` (image, by digest) |
| OWASP Dependency-Check 12.1.0 | agent-security (CLI) | NVD mirror volume `/owasp-dc`, host-updated nightly (same pinned version) | merged into `dependencies.*` with trivy fs; exceptions by CVE |
| syft 1.55.0 | agent-security | image by digest from platform registry | `sbom.required` → hard gate; SBOMs archived + raw-hosted |
| cosign 3.1.4 | agent-security | platform keypair (D-25; Vault from Phase 11) | `signing.required` → hard gate; signs digests only |

Enforcement invariants:
* Scanner exit codes NEVER decide policy — `FindingGate` + `SecurityPolicy`
  (block_on_* flags, tighten-only project overrides, validated exception
  register) are the single decision point.
* Reports are archived machine-readable (JSON) plus a normalized
  `security-verdict-<svc>.json`; console output is log-safe (no secret
  material, no code excerpts — ids/files/lines only; gitleaks `--redact`).
* "Never silently ignore": unfixed vulns are reported (`container.ignore_unfixed`
  default false), expired exceptions gate again, disabled tools announce an
  explicit skip with the policy reason.
* Signing/verification chain: cosign signature created by digest at CI;
  Phase 8 Kyverno `verifyImages` admits only digests signed with
  `secrets/cosign/cosign.pub` — unsigned images cannot be deployed.

## 6. Deployment-time enforcement (Phase 8)

CI gates (Phase 7) decide what MAY ship; the cluster decides what MAY run.
Both are policy-driven and fail closed:

| Control | Mechanism | Failure mode |
|---|---|---|
| Signed images only | Kyverno `verify-image-signature` (Enforce): cosign verification of every `registry.<domain>/*` image against the platform public key (inline from `secrets/cosign/cosign.pub`, re-inject after rotation: `kubernetes/kyverno/cosign-public-key.sh`) | admission webhook rejects the pod — deployment never starts |
| Immutable references | Kyverno `require-digest-pinning` (Enforce): workload containers must match `registry.<domain>/*@sha256:*` — no mutable tags, no foreign registries | pod rejected; only CI (`updateGitOps`/`promoteDigest`) writes digests |
| No cluster admin in CI | Jenkins holds ONLY `jenkins-cd` (ArgoCD API: applications get/sync in dev/qa/uat/prod projects) + a read-only verifier kubeconfig (Phase 9); git push rights are per-project (Maintainer on gitops-repository only) | a compromised pipeline cannot mutate the cluster directly — git history + ArgoCD diffs remain the audit trail |
| No secrets in git | Chart values carry key NAMES; ExternalSecrets fetch from Vault KV v2 `secret/apps/<service>/<name>`; Vault policy `eso-app-secrets` reads `apps/*` ONLY; ESO authenticates via per-cluster Kubernetes auth (TokenReview, 1h TTL) — no static Vault token in the cluster | ESO sync errors surface on the ExternalSecret status; Vault audit log records every read |
| Registry pull path | Node `registries.yaml` (0600, root-only): docker.io/quay.io/ghcr.io mirrored through Nexus with the jenkins-ci basic-auth — cluster never reaches the internet directly (D-16/D-27) | pull 401/timeout instead of silent external fallback |
| Namespace isolation | AppProject per env: `*-<env>` namespaces only, no cluster-scoped resources (`clusterResourceWhitelist: []`); chart floor: runAsNonRoot 10001, readOnlyRootFilesystem, drop ALL caps, seccomp RuntimeDefault, default-deny NetworkPolicy | ArgoCD refuses out-of-project destinations; privileged pods fail the chart's own securityContext contract |

## 7. Vault: dynamic secrets & rotation (Phase 11, D-36)

The Vault hierarchy separates WHO may read WHAT:

```
secret/ (KV v2)
├── apps/<service>/<name>     ← ESO ONLY (policy eso-app-secrets, per-cluster
│                                Kubernetes auth, TokenReview, no static tokens)
└── platform/
    ├── notifications         ← Jenkins AppRole (policy jenkins-platform)
    └── cosign                ← Jenkins AppRole (signing key migration target)

auth/
├── kubernetes-<cluster>/     role eso-reader  (Phase 8, one mount per cluster)
└── approle/                  role jenkins-platform: token_ttl=1h, max 4h,
                              policies=[jenkins-platform] (read platform/* only)
```

* **Provisioning order** (after unseal): `vault/scripts/40-platform-secrets.sh`
  (migrates .env/secrets values into `secret/platform/*`) →
  `50-jenkins-approle.sh` (role-id/secret-id → `secrets/vault-jenkins.env` →
  JCasC credential `vault-approle` → global `vaultConfiguration`) →
  `60-audit-enable.sh` (audit → Alloy tail → Loki `{service="vault-audit"}`).
* **Build-time dynamic secrets**: `withVault(configuration: [vaultUrl:
  'http://vault:8200', vaultCredentialId: 'vault-approle', engineVersion: 2],
  vaultSecrets: [[path: 'secret/platform/notifications', secretValues:
  [[vaultKey: 'slack_webhook_url', envVar: 'SLACK_URL']]]]) { … }` — every
  access mints a 1h, policy-scoped token; nothing long-lived enters the build.
* **Rotation runbook**: secret-id → rerun `50-jenkins-approle.sh` +
  `docker compose up -d jenkins`; cosign keypair →
  `security/scripts/10-cosign-keys.sh` (rotate) → `40-platform-secrets.sh
  FORCE=1` → `kubernetes/kyverno/cosign-public-key.sh` (cluster trust);
  unseal keys → `vault operator rekey` (off-host ceremony, new envelopes);
  root token → create new root policy token, revoke initial.
* **Residual static files** (honest ledger): `secrets/*.env` remain the
  bootstrappable fallback for JCasC env interpolation (D-34/D-36) — Vault is
  the source of truth once seeded, but a sealed-Vault cold start reads files.
  Phase-future work: Vault Agent auto-auth templating removes the last static
  copies (tracked as a hardening backlog item, not a gap: every file is 0600,
  gitignored, and every value is rotatable via the runbooks above).
* **Audit fail-closed**: while an audit device is enabled but unwritable,
  Vault refuses ALL requests — by design. HostDiskSpaceLow (critical) guards it.

## 8. Enterprise realm cutover: LDAP / OIDC (Phase 11, D-38)

The local realm (`casc/10-security.yaml`) is the bootstrappable baseline; the
six-role authorization matrix maps *principals*, so the cutover touches ONLY
the realm + principal names:

1. **LDAP** — no new plugin (ships with core). Edit
   `jenkins/optional-casc/10-security-ldap.yaml` (server/rootDN/bind creds via
   `secrets/jenkins.env`), then mount it one-for-one over `10-security.yaml`
   in the jenkins volumes and recreate. Create the six LDAP groups
   (`platform-admin`, `devops-admin`, `developer`, `security-engineer`,
   `release-manager`, `app-owner`) and switch matrix `user:` → `group:`.
2. **OIDC** — uncomment the pinned `oic-auth:4.731.v4932b_506e767` in
   plugins.txt (verified: requires ≥2.539, platform runs 2.568.3), rebuild the
   controller image, register the client (redirect
   `https://jenkins.<domain>/securityRealm/finishLogin`), fill
   `jenkins/optional-casc/10-security-oidc.yaml`, same one-for-one mount swap.
   `escapeHatchEnabled` keeps a local break-glass login.
3. Either way the permission matrix is unchanged (master spec §17) — see the
   role→access matrix in §2 of this guide.

## 9. TLS posture & certificate rotation (Phase 11)

* Termination: Traefik only (architecture §4.3). Internal listeners are plain
  HTTP on internal Docker networks; the wildcard cert
  (`reverse-proxy/certificates/`) covers `*.${PLATFORM_DOMAIN}`.
* Hardened options (dynamic.yml.tmpl): `minVersion: VersionTLS12`, forward-
  secret AEAD-only cipher suite list (ECDHE+AES-GCM/ChaCha20-Poly1305),
  curve preferences P-521/P-384, HSTS 1y + includeSubdomains, nosniff,
  frame-deny, Server header stripped; admin surfaces (vault, prometheus,
  alertmanager) behind `admin-ipallowlist` and/or `monitoring-auth` basic auth.
* `TLS_MODE=internal-ca` (default): rotate the wildcard by re-running the
  bootstrap certificate block (or `openssl` manually with the same CA), then
  `docker compose restart traefik` — clients already trust the 10-year CA.
  Rekey the CA itself = redistribute `ca.crt` to every client + cluster node
  (`kubernetes/k3s` writes it into node `/etc/hosts` + trust store).
* `TLS_MODE=letsencrypt`: Traefik ACME resolver against the public DNS names;
  same middlewares/routers apply — only the certificate source changes.
* Verification: `echo | openssl s_client -connect gitlab.${PLATFORM_DOMAIN}:443
  -tls1_2 2>/dev/null | grep -E "Cipher|Protocol"` → ECDHE-*-GCM/CHACHA; and
  `nmap --script ssl-enum-ciphers -p 443` shows no TLS<1.2, no CBC, no 3DES.
